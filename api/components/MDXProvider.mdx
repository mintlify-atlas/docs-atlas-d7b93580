## Overview

`MDXProvider` is a context provider that allows you to customize how MDX elements are rendered throughout your component tree. It provides a way to override default HTML elements with custom React components.

This is particularly useful for:
- Styling MDX content consistently
- Adding functionality to standard elements
- Creating interactive documentation
- Implementing design systems in MDX

## Props

<ParamField path="value" type="Object" required>
  An object mapping element names to React components. Keys are HTML element names (like `h1`, `p`, `code`) and values are component functions.
</ParamField>

<ParamField path="children" type="ReactNode" required>
  The component tree that will have access to the custom MDX components.
</ParamField>

## Usage

### Basic component customization

```jsx
import { MDXProvider } from 'ryunixjs'

const components = {
  h1: (props) => <h1 className="custom-heading" {...props} />,
  p: (props) => <p className="custom-paragraph" {...props} />,
  code: (props) => <code className="custom-code" {...props} />
}

function App({ children }) {
  return (
    <MDXProvider value={components}>
      {children}
    </MDXProvider>
  )
}
```

### Interactive components

```jsx
import { MDXProvider } from 'ryunixjs'
import { useStore } from 'ryunixjs/hooks'

function InteractiveCode({ children, ...props }) {
  const [copied, setCopied] = useStore(false)
  
  const handleCopy = () => {
    navigator.clipboard.writeText(children)
    setCopied(true)
    setTimeout(() => setCopied(false), 2000)
  }
  
  return (
    <div className="code-block">
      <code {...props}>{children}</code>
      <button onClick={handleCopy}>
        {copied ? 'Copied!' : 'Copy'}
      </button>
    </div>
  )
}

const components = {
  code: InteractiveCode
}

function App({ children }) {
  return (
    <MDXProvider value={components}>
      {children}
    </MDXProvider>
  )
}
```

### Nested providers

```jsx
import { MDXProvider } from 'ryunixjs'

  h1: (props) => <h1 className="article-h1" {...props} />,
  // p will inherit from global

  return (
    <MDXProvider value={globalComponents}>
      <Header />
      <MDXProvider value={articleComponents}>
        <Article />
      </MDXProvider>
      <Footer />
    </MDXProvider>
  )
}
```

## Helper functions

### useMDXComponents

Hook to access the current MDX components from context:

```jsx
import { useMDXComponents } from 'ryunixjs'

function MyComponent() {
  const components = useMDXComponents()
  const CustomH1 = components.h1
  
  return <CustomH1>Hello World</CustomH1>
}
```

### getMDXComponents

Function to merge context components with additional components:

```jsx
import { getMDXComponents } from 'ryunixjs'

function MyMDXComponent({ components: customComponents }) {
  const components = getMDXComponents(customComponents)
  
  // components now contains both context and custom components
  return <div>{/* use components */}</div>
}
```

## MDXContent wrapper

RyunixJS provides an `MDXContent` component for wrapping MDX content:

```jsx
import { MDXContent } from 'ryunixjs'

const customComponents = {
  h1: CustomHeading,
  code: CustomCode
}

function Page({ children }) {
  return (
    <MDXContent components={customComponents}>
      {children}
    </MDXContent>
  )
}
```

MDXContent automatically:
- Merges provided components with context components
- Wraps content in a div container
- Applies the MDXProvider context

## Implementation details

### Context creation

MDXProvider is created using RyunixJS's `createContext`:

```js
const { Provider: MDXProvider, useContext: useMDXComponents } = createContext(
  'ryunix.mdx',
  {}
)
```

Source: `packages/core/src/lib/components.js:106-109`

### Component merging

When using nested providers or getMDXComponents, components are merged:

```js
const getMDXComponents = (components) => {
  const contextComponents = useMDXComponents()
  return {
    ...contextComponents,
    ...components
  }
}
```

This allows child providers to override parent components while inheriting unspecified ones.

## Best practices

### Provide components at the root

Set up your MDX components once at the application root:

```jsx
// Good
function App() {
  return (
    <MDXProvider value={components}>
      <Router />
    </MDXProvider>
  )
}

// Less optimal - setting up on each page
function Page() {
  return (
    <MDXProvider value={components}>
      <PageContent />
    </MDXProvider>
  )
}
```

### Keep components pure

MDX component overrides should be pure and predictable:

```jsx
// Good - pure component
const CustomHeading = (props) => (
  <h1 className="heading" {...props} />
)

// Avoid - side effects in render
const BadHeading = (props) => {
  trackPageView() // Side effect!
  return <h1 {...props} />
}
```

### Use semantic HTML

Even when customizing, maintain semantic HTML:

```jsx
// Good - still renders h1
const CustomH1 = (props) => (
  <h1 className="custom" {...props} />
)

// Bad - changes semantic meaning
const BadH1 = (props) => (
  <div className="looks-like-h1" {...props} />
)
```

### Spread props consistently

Always spread props to maintain MDX functionality:

```jsx
// Good - preserves all props
const Component = ({ className, ...props }) => (
  <div className={`custom ${className}`} {...props} />
)

// Bad - drops unknown props
const Bad = ({ children }) => (
  <div>{children}</div>
)
```

## Performance

### Component memoization

Memoize component overrides to prevent unnecessary re-renders:

```jsx
import { useMemo } from 'ryunixjs/hooks'

function App() {
  const components = useMemo(() => ({
    h1: (props) => <h1 className="heading" {...props} />,
    p: (props) => <p className="paragraph" {...props} />
  }), [])
  
  return (
    <MDXProvider value={components}>
      {/* content */}
    </MDXProvider>
  )
}
```

### Avoid inline component definitions

```jsx
// Bad - creates new component on every render
<MDXProvider value={{
  h1: (props) => <h1 className="heading" {...props} />
}}>
  {children}
</MDXProvider>

// Good - stable component reference
const components = {
  h1: (props) => <h1 className="heading" {...props} />
}

<MDXProvider value={components}>
  {children}
</MDXProvider>
```
