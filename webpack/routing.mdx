Ryunix uses powerful AST-driven plugins to automatically generate routing configurations from your file system structure.

## File-System Routing

The Webpack preset scans your `app/` directory at build time and generates optimized routing trees.

### Directory Structure

```
app/
├── layout.ryx          # Root layout (wraps all pages)
├── page.ryx            # Home page (/)
├── about/
│   └── page.ryx        # /about
├── blog/
│   ├── layout.ryx      # Blog layout
│   ├── page.ryx        # /blog
│   └── [slug]/
│       └── page.ryx    # /blog/:slug (dynamic)
└── dashboard/
    ├── layout.ryx
    ├── loading.ryx     # Loading state
    ├── error.ryx       # Error boundary
    └── page.ryx        # /dashboard
```

## AppRouterPlugin

The `AppRouterPlugin` is responsible for analyzing the `/app` directory and generating the routing configuration.

**Source:** `/packages/ryunix-presets/webpack/utils/appRouterPlugin.mjs`

### How It Works

<Steps>
  <Step title="Auto-Detection">
    Parses source code using Regex to detect:
    - **Hooks** (`useStore`, `useEffect`) → Client Component
    - **Async Exports** (`export async default`) → Server Component
  </Step>
  
  <Step title="Boundary Generation">
    Maps special files to React boundaries:
    - `layout.ryx` → Layout wrapper
    - `error.ryx` → `<ErrorBoundary>`
    - `loading.ryx` → `<Suspense fallback>`
  </Step>
  
  <Step title="Metadata Aggregation">
    Resolves and merges exported `Metatags` or `generateMetadata()` from parent layouts to child pages.
  </Step>
  
  <Step title="Isomorphic Shell">
    Outputs dual configurations:
    - **Server:** Direct component references for SSR
    - **Client:** Lazy-loaded chunks via `AsyncComponentRenderer`
  </Step>
</Steps>

### Generated Output

The plugin generates `.ryunix/server/app/app-router.js`:

```javascript
// Auto-generated by AppRouterPlugin
export const routes = [
  {
    path: '/',
    component: () => import('./pages/index.ryx'),
    layout: () => import('./layout.ryx'),
    metadata: { title: 'Home' }
  },
  {
    path: '/blog/:slug',
    component: () => import('./pages/blog/[slug]/page.ryx'),
    loading: () => import('./pages/blog/loading.ryx'),
    error: () => import('./pages/blog/error.ryx')
  }
]
```

**Configuration:**

```javascript
new AppRouterPlugin({
  appDir: resolveApp(dir, 'app'),
  outputPath: resolveApp(dir, '.ryunix/server/app/app-router.js'),
  ssgOutputPath: resolveApp(dir, '.ryunix/cache/ssg/routes.json'),
  debug: config.debug
})
```

**Source:** `/packages/ryunix-presets/webpack/webpack.config.mjs:508-513`

## Special Files

### `layout.ryx`

Defines a layout that wraps all child routes.

```javascript
// app/layout.ryx
export default function RootLayout({ children }) {
  return (
    <html>
      <head>
        <title>My App</title>
      </head>
      <body>
        <nav>...</nav>
        {children}
        <footer>...</footer>
      </body>
    </html>
  )
}
```

**Nested Layouts:**

```javascript
// app/dashboard/layout.ryx
export default function DashboardLayout({ children }) {
  return (
    <div class="dashboard">
      <Sidebar />
      <main>{children}</main>
    </div>
  )
}
```

---

### `page.ryx`

Defines the actual page content.

```javascript
// app/about/page.ryx
export default function AboutPage() {
  return <h1>About Us</h1>
}
```

---

### `loading.ryx`

Defines a loading state shown during Suspense.

```javascript
// app/dashboard/loading.ryx
export default function Loading() {
  return <div>Loading dashboard...</div>
}
```

**Compiles to:**

```javascript
<Suspense fallback={<Loading />}>
  {children}
</Suspense>
```

---

### `error.ryx`

Defines an error boundary for the route segment.

```javascript
// app/dashboard/error.ryx
export default function Error({ error, reset }) {
  return (
    <div>
      <h2>Something went wrong!</h2>
      <p>{error.message}</p>
      <button onClick={reset}>Try again</button>
    </div>
  )
}
```

**Compiles to:**

```javascript
<ErrorBoundary fallback={<Error />}>
  {children}
</ErrorBoundary>
```

## Dynamic Routes

### Single Parameter

Use `[param]` syntax for dynamic segments:

```
app/
└── blog/
    └── [slug]/
        └── page.ryx
```

**Matches:** `/blog/hello-world`, `/blog/my-post`

**Access params:**

```javascript
// app/blog/[slug]/page.ryx
export default function BlogPost({ params }) {
  const { slug } = params
  return <h1>Post: {slug}</h1>
}
```

---

### Catch-All Routes

Use `[...param]` for catch-all segments:

```
app/
└── docs/
    └── [...path]/
        └── page.ryx
```

**Matches:** `/docs/a`, `/docs/a/b`, `/docs/a/b/c`

```javascript
export default function Docs({ params }) {
  const { path } = params // ['a', 'b', 'c']
  return <h1>Docs: {path.join('/')}</h1>
}
```

## Metadata

### Static Metadata

Export a `metadata` object:

```javascript
// app/about/page.ryx
export const metadata = {
  title: 'About Us',
  description: 'Learn more about our company',
  keywords: ['company', 'about']
}

export default function AboutPage() {
  return <h1>About</h1>
}
```

---

### Dynamic Metadata

Export an async `generateMetadata` function:

```javascript
// app/blog/[slug]/page.ryx
export async function generateMetadata({ params }) {
  const post = await fetchPost(params.slug)
  
  return {
    title: post.title,
    description: post.excerpt,
    openGraph: {
      title: post.title,
      image: post.coverImage
    }
  }
}

export default function BlogPost({ params }) {
  // ...
}
```

**Metadata Merging:**

The plugin automatically merges metadata from parent layouts down to child pages:

1. Root `layout.ryx` metadata
2. Nested `layout.ryx` metadata
3. Final `page.ryx` metadata (highest priority)

**Source Reference:** See routing documentation for metadata aggregation logic

## API Routes

The `ApiRouterPlugin` handles backend API endpoints.

**Source:** `/packages/ryunix-presets/webpack/utils/ApiRouterPlugin.mjs`

### Directory Structure

```
app/
└── api/
    ├── route.js         # /api/
    ├── users/
    │   └── route.js     # /api/users
    └── posts/
        ├── route.js     # /api/posts
        └── [id]/
            └── route.js # /api/posts/:id
```

### Route Handlers

```javascript
// app/api/users/route.js
export async function GET(request) {
  const users = await db.users.findMany()
  return Response.json(users)
}

export async function POST(request) {
  const body = await request.json()
  const user = await db.users.create(body)
  return Response.json(user, { status: 201 })
}
```

**Supported Methods:** `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`

---

### Dynamic API Routes

```javascript
// app/api/posts/[id]/route.js
export async function GET(request, { params }) {
  const post = await db.posts.findById(params.id)
  
  if (!post) {
    return Response.json({ error: 'Not found' }, { status: 404 })
  }
  
  return Response.json(post)
}

export async function DELETE(request, { params }) {
  await db.posts.delete(params.id)
  return Response.json({ success: true })
}
```

**Configuration:**

```javascript
new ApiRouterPlugin({
  appDir: resolveApp(dir, 'app'),
  outputPath: resolveApp(dir, '.ryunix/server/api'),
  debug: config.debug
})
```

## Client vs Server Components

The `AppRouterPlugin` automatically detects component types:

### Client Components

**Auto-detected when using:**
- `useStore`
- `useEffect`
- `useLayoutEffect`
- `useContext`
- `useRef`
- `useMemo`
- `useTransition`

**Or explicitly mark:**

```javascript
// @client
export default function Counter() {
  const [count, setCount] = Ryunix.useState(0)
  return <button onClick={() => setCount(count + 1)}>{count}</button>
}
```

---

### Server Components

**Auto-detected when:**
- Exporting async default function
- No client-side hooks detected

**Or explicitly mark:**

```javascript
// @server
export default async function UserList() {
  const users = await db.users.findMany()
  return <ul>{users.map(u => <li>{u.name}</li>)}</ul>
}
```

## DevServer Integration

The Webpack Dev Server seamlessly integrates routing:

### Middlewares

1. **Server Actions** (`/_ryunix/action`)
2. **API Routes** (`/api/*`)
3. **SSR Rendering** (all other routes)

**Source:** `/packages/ryunix-presets/webpack/webpack.config.mjs:396-456`

### Hot Module Replacement

The dev server automatically reloads when files change:

```javascript
devServer: {
  watchFiles: [
    resolveApp(dir, 'src/**/*'),
    resolveApp(dir, 'app/**/*')
  ],
  hot: true,
  liveReload: false
}
```

## Legacy Routes Plugin

For backwards compatibility, `RyunixRoutesPlugin` supports page-based routing:

```javascript
new RyunixRoutesPlugin({
  routesPath: resolveApp(dir, 'src/pages/routes.ryx'),
  outputPath: resolveApp(dir, '.ryunix/cache/ssg/routes.json'),
  debug: config.debug
})
```

<Warning>
This is **deprecated**. Use the `app/` directory for new projects.
</Warning>
